One spec, one agent

Each agent sees only its own spec, in its own session.

Tests are the standard

The tester writes tests from the spec in its own worktree, where the new code does not exist, then re-checks them. When a test fails, the code is presumed wrong.

Code owns the skeleton

Order, file ownership and the repair limit live in the script.

Passing is computed

Exit codes and criteria decide. No agent declares its own work passing.

Agents before any repair: 6 to 7 for one spec, 4N+3 to 5N+3 for N specs. A small recorder agent, not part of the team, writes this dashboard's progress file at each step. The outcome is passed, failed, or blocked when the run needs a decision code cannot make.

Rules enforced in code

  • validateSpecs()Every criterion is covered by a spec
  • validateSpecs()One owner per file, including between implementer and tester
  • maxSpecRevisionsRejected specs go back to the planner, at most 2 times
  • buildLevels()Dependent specs wait; specs on one level run in parallel
  • specText()The implementer is not shown Tests, the tester is not shown Changes
  • setupScript()Each tester works in its own git worktree at the base commit
  • readGather()Git, not the tester, says what changed in the worktree. A test file changed in the repository during the build stops the run
  • testSpec()The tester re-checks until a pass changes nothing, at most 2 passes
  • filesOutsideAssignment()An agent that reports changing a file it does not own stops the run
  • filesOutsideOwnership()A changed file that no spec owns stops the run
  • evaluate()Passed: every check exits 0, every criterion met by every reviewer, no blocking finding
  • splitFailures()Failures go into the fixer's report. Only a finding against a test file goes back to its tester
  • maxRepairRoundsAt most 2 repair rounds
  • runRecord()What this dashboard shows is built from the raw results, not written by an agent
