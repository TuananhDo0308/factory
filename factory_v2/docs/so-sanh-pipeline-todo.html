2. Vấn đề của pipeline cũ

Số vòng sửa ở pipeline cũ gần như bằng 0: chỉ issue #3 có một vòng. Pipeline cũ chậm vì quy trình, không phải vì code sai.

P1 Issue chạy nối tiếp

BA chia theo issue, factory làm từng issue một. 3 issue nối nhau, mỗi issue 44–63 phút.
Chi phí: tổng thời gian bằng tổng các issue.

P2 Chi phí cố định mỗi issue lớn

Mỗi issue có planner, dựng contract, PR và CI riêng. Planner 12–17 phút; ngoài Workflow 10–25 phút mỗi issue.
Chi phí: khoảng 25–40 phút mỗi issue trước khi tính đến code.

P3 Planner chia spec theo tầng

Log ghi: "2 spec(s) in 2 build level(s): S1 → S2", "nothing runs in parallel".
Chi phí: Build 7–15 phút, không có gì chạy song song.

P4 Quá nhiều người chấm mỗi criterion

4–5 agent chấm mỗi criterion: QA của spec, review của spec, reviewer chung, checker và QC.
Chi phí: pha Review 7–14 phút, khoảng 25–35% thời gian Workflow.

P5 Agent làm việc của code

Workflow không đọc ghi file, không chạy được lệnh. 31 agent record và 3 agent checker: 40% số agent chỉ để ghi tiến độ.
Chi phí: mỗi agent tốn từ vài chục giây đến vài phút.

P6 QC bấm tay ở mỗi issue

QC qua Playwright MCP 6–9 phút mỗi issue, lặp lại 3 lần.
Chi phí: khoảng 20 phút cho 3 issue.

P7 Kẹt và cần người

Lệnh check treo, phải kill tay 2 lần; 3 lần chờ người gõ "tiếp tục"; 2 lần gọi Workflow lỗi.
Chi phí: khoảng 10–25 phút mỗi issue ngoài Workflow.

P8 Một vòng sửa làm lại cả chuỗi review

Issue #3: QC fail, 2 rebuild (opus), rồi QA, checker, reviewer, 3 review spec và QC chạy lại từ đầu.
Chi phí: vòng 2 của #3 mất khoảng 14 phút.

3. Khắc phục bằng pipeline mới

Pipeline mới đổi cả hai đầu. BA (new-ba) chia theo lát tính năng, cộng một ticket nền móng giữ các hợp đồng chung, để hầu hết ticket build cùng lúc. Factory (new-factory) là một chương trình Node: chạy kế hoạch theo đồ thị phụ thuộc, việc chắc chắn thì làm bằng code, chỉ dùng agent cho implementer, reviewer, chẩn đoán và QC.
